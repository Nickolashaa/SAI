# Лабораторная работа №2 — распознавание объекта по устойчивым признакам

Задание: приложение получает на вход изображение-образец с объектом и находит
этот объект двумя способами — на статичном изображении и в реальном времени
с камеры. Используются ключевые точки и дескрипторы (SIFT), сопоставление
дескрипторов и поиск гомографии методом RANSAC.

## Запуск

```bash
uv sync
uv run lab2 образец.jpg                  # реальное время с камеры
uv run lab2 образец.jpg --scene сцена.jpg  # статичное изображение
```

Первый аргумент — всегда изображение-образец. Если объект сложно
сфотографировать заранее, можно запустить программу с любым образцом и
вырезать новый прямо из кадра клавишей `c`.

## Управление

| Клавиша | Действие |
| --- | --- |
| `q`, `Esc` | выход |
| `s` | сохранить снимок в `snapshots/` |
| `t` | сменить детектор (SIFT → AKAZE → ORB → BRISK) |
| `k` | показать/скрыть ключевые точки |
| `l` | показать/скрыть линии соответствий |
| `i` | все совпадения / только инлаеры |
| `c` | вырезать новый образец из текущего кадра |
| `m` | зеркальное отображение |
| `h` | панель статистики |
| `p`, пробел | пауза |
| `+` / `-` | порог теста Лоу |

## Параметры запуска

```
--scene PATH          статичное изображение или видеофайл вместо камеры
--camera N            индекс веб-камеры (по умолчанию 0)
--width / --height    разрешение кадра камеры
--detector            sift | akaze | orb | brisk
--ratio               порог теста Лоу (по умолчанию 0.75)
--min-inliers         минимум инлаеров RANSAC для признания объекта
--max-features        ограничение числа ключевых точек
--detect-every N      искать объект раз в N кадров
--no-mirror           не отражать кадр камеры
--snapshot-dir DIR    папка для снимков
--output FILE.mp4     запись результата в видеофайл
--no-display          работа без окна
--max-frames N        остановиться после N кадров
```

## Структура

```
src/lab2/
├── __init__.py   аргументы командной строки, main()
├── app.py        главный цикл: кадр → поиск объекта → отрисовка → клавиши
├── matcher.py    ключевые точки, дескрипторы, сопоставление, гомография
├── render.py     композиция «сцена + образец», рамка, линии, статистика
└── source.py     камера / видеофайл / изображение
```

## Как это работает

На образце и на кадре сцены ищутся ключевые точки и считаются дескрипторы
(`detectAndCompute`). Дескрипторы сопоставляются перебором с `knnMatch` по двум
ближайшим соседям, после чего применяется тест Лоу: совпадение принимается,
только если ближайший сосед заметно ближе второго (по умолчанию в 0.75 раза).
По оставшимся парам методом RANSAC ищется гомография (`findHomography`), углы
образца переносятся на сцену (`perspectiveTransform`) и рисуются красной
рамкой. Объект считается найденным, если гомография опирается не менее чем на
`--min-inliers` согласованных точек, а полученный четырёхугольник выпуклый и
разумного размера.

SURF из методички в `opencv-python` недоступен — алгоритм запатентован и
исключён из сборки. Вместо него, кроме SIFT, доступны AKAZE, ORB и BRISK:
они свободны от патентов и работают быстрее.

Нужен OpenCV 4.x: в OpenCV 5 изменился состав модулей.
